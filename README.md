# openspec-config

Share one OpenSpec [`openspec/config.yaml`](https://openspec.dev/docs/configuration/config-yaml) across multiple repos — updated like a dependency, not by hand.

OpenSpec keeps each repo's config in `openspec/config.yaml`, with no built-in way to keep those files consistent across projects. This package ships a shared **base config** plus a small CLI that regenerates each repo's `config.yaml` from it. Because the base arrives as an npm dependency, its version is pinned in your lockfile and updating it is just a dependency bump.

No CI is required: consistency is enforced by a local git pre-commit hook, and updates are pulled with plain npm commands.

## Consumer setup

In a repo that uses OpenSpec (needs a `package.json` — run `npm init -y` first if there isn't one):

```bash
npm install --save-dev openspec-config

npx openspec-config sync --force   # adopt (once; folds in any override, see below)
npx openspec-config hook           # once per clone: pre-commit drift guard
```

This writes `openspec/config.yaml` with a generated header:

```yaml
# Generated by openspec-config@1.0.0. Do not edit by hand.
# Source: https://github.com/davegoopot/openspec-config — rerun `openspec-config sync` to update.
schema: spec-driven
```

Commit the generated file, and treat it like a lockfile: never hand-edit it.

## Commands

| Command | What it does |
|---|---|
| `openspec-config sync` | Regenerate `openspec/config.yaml` from the base + override |
| `openspec-config check` | Exit 0 if the file matches what `sync` would produce, 1 + diff otherwise |
| `openspec-config hook` | Install the pre-commit drift check (again per clone; idempotent) |
| `openspec-config hook --remove` | Strip the drift check from the pre-commit hook |

Options: `--dir <path>` (target project root, default `.`), `--force` (overwrite a config lacking the generated header — use once when adopting), `--base <path>` (install an alternative base, advanced).

`sync` refuses to overwrite a `config.yaml` that wasn't generated by this tool, so it can't silently destroy a hand-written config. The hook plays nicely with existing pre-commit content: it adds a marker-delimited block, replaces only its own block on re-install, and deletes only that block on `--remove`.

## Per-repo overrides

Repos can add their own keys on top of the base in `openspec/config.override.yaml` (committed like any other file):

```yaml
# openspec/config.override.yaml
store: team-plans        # e.g. this repo plans in an OpenSpec store

rules:
  proposal:              # replaces the base's rules.proposal list wholesale
    - Keep proposals under 500 words
    - Always state what is out of scope
```

Merge semantics, kept deliberately simple:

- nested **maps deep-merge**
- **scalars and arrays replace** the base value at the deepest key provided
- setting a key to `null` **deletes** it from the base

Override anything OpenSpec supports (`store`, `references`, `context`, `rules`, `operations`, …).

## Staying consistent without CI

`openspec-config hook` writes a small block into `.git/hooks/pre-commit`:

```sh
# >>> openspec-config >>>
# Installed by `openspec-config hook`: blocks commits when openspec/config.yaml is out of sync.
if command -v node >/dev/null 2>&1; then
  cd "$(git rev-parse --show-toplevel)" || exit 1
  npx --no-install openspec-config check || {
    echo "openspec/config.yaml is out of sync (or openspec-config is not installed)."
    echo "Run: npx openspec-config sync"
    exit 1
  }
fi
# <<< openspec-config <<<
```

Any commit in that repo is blocked while `openspec/config.yaml` doesn't match what the installed package version would produce — hand-edits, forgotten syncs, or a dependency version that moved ahead. The block prints the diff and the fix; no server involved.

## Pulling base updates

When a new version of openspec-config is published, in each consumer repo:

```bash
npm install --save-dev openspec-config@latest
npx openspec-config sync
git add openspec/config.yaml && git commit -m "chore: sync openspec config"
```

Or the lazy way: bump the dependency (`npm update openspec-config`, or edit `package.json` for a major), keep working — the pre-commit hook blocks your next commit and tells you to run `npx openspec-config sync`, so drift can't reach the remote.

## Changing the shared base

1. Open a PR against [`config/base.yaml`](config/base.yaml) in this repo. Comments there are maintainer documentation only — they don't propagate to generated files, so put real content in actual values.
2. Merge, then version and publish:

```bash
npm version minor        # or major/patch — see policy below
npm publish
```

3. Pull the update in the consumer repos as above.

**Semver policy:** changes that add rules are `minor`; changes that alter or remove behavior (editing existing rules, changing `context`, removing keys) are `major`. The diff each consumer sees after `sync` is exactly what the agent's behavior change will be.

Keep the base short: everything in it lands in every agent prompt on every run ([OpenSpec's advice](https://openspec.dev/docs/project-config)).

## Development

```bash
npm install
npm test
```

`config/base.yaml` is the shared source of truth; `lib/core.mjs` holds the merge, emit, diff, and hook logic; `bin/cli.mjs` is the thin CLI entry. Tests run locally; this repo uses no CI.
